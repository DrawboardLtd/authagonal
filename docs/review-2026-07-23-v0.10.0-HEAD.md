### M3 — design for the dedicated pass

The upstream refresh token is pinned on the SSO cookie at login and lifted onto *every* later `/connect/authorize`
grant; once one grant's refresh rotates it (Entra/Auth0 one-time-use), the cookie copy is dead and any new grant
seeded from it dies on next refresh. The fix is a durable per-**(user, connection, sid)** entry (not just
user+connection — a user's second device/session has its own upstream token, so the key MUST include `sid` or
sessions clobber each other), updated on every successful rotation and read by both `ResolveAsync` and
`ResolveRefreshAsync` instead of the cookie/prior-grant copy. Held because it is the one change that adds
persistent state across storage providers on a security-sensitive path: the reuse-`IGrantStore` shortcut interacts
with grant iteration/cleanup/expiry semantics (and `GetBySubjectAsync` consumers), and a dedicated store needs
Azure+AWS impls + DI — neither is safe to land un-runtime-tested at the tail of a batch. bullclip is single-RP, so
the bug is not currently triggered; M4 (`06cd35f`) already narrows its blast radius.

### New findings the original pass missed

- **N1 — Pre-verification attribute/name merge onto the victim account (residual of M2, survives the H2 fix).**
  `AuthEndpoints.cs:410-416`. On a passwordless claim, attacker-supplied `FirstName`/`LastName`/
  `CustomAttributes` are merged onto the *existing victim account* and persisted at **register**
  time, before any inbox verification, with **no key whitelist** on `CustomAttributes`. Those
  attributes flow onto the real owner's federated-login tokens (scope-gated `federated:*`
  emission). Knowing a federated account's email is enough to mutate its display name and custom
  claims pre-auth. Lower severity than credential takeover, but neither the H2 fix nor the review's
  M2 remediation addresses it (the mutation is persisted at register and never rolled back). Fix:
  stage profile/attribute changes alongside `PendingPasswordHash` (apply on confirm), and whitelist
  `CustomAttributes` keys.
- **N2 — `auth_time` was declared-supported but never minted.** It appears in discovery
  `ClaimsSupported` and the token passthrough allowlists, but no sign-in path set it — so
  id_tokens never carried `auth_time` (a spec-correctness gap) and prompt=login had no freshness
  signal to enforce against. Fixed in tranche 1 (minted at `CookieSignInHelper` + the OIDC/SAML
  federation sign-ins).
- **N3 — Real shipped product-name leak (the true version of S3).** `Authagonal.Core.csproj:11`
  has `<Authors>Drawboard</Authors>`, which ships in the NuGet package metadata / nuget.org
  listing. This — not the XML-doc comments S3 flags — is the leak that actually reaches consumers.

### Corrections to the original findings

- **H1 is not "infinite."** Bounded by the PAR record's 90s TTL, after which `/authorize`
  hard-errors (`request_uri … expired`). Functionally worse than a loop: a code is **never** issued
  for PAR+prompt=login. The remediation's "forever" framing should read "until the 90s
  `request_uri` lifetime elapses, then errors."
- **M1's "skip the form" is not reachable through the bundled login-app**, which forces the
  credential form on OAuth flows (`LoginPage.tsx:107-125`). The exploit needs a custom client that
  ignores the SPA and hits the server-stripped authorize URL directly. The server-side defect (no
  sign-out, no `auth_time`) is real; the trivial-bypass framing is not.
- **M7 is narrower than stated.** The `idp_hint` federation branch drops `loginHint` for **both**
  protocols; only the SSO-domain straight-to-IdP branch forwards it, and only SAML consumes it.
- **M8 is broader than the two cited paths.** The same `isSafeReturnUrl` gate also drops absolute
  registered-app returnUrls in `handleProviderLogin`, `handleSsoRedirect`, `forgotPasswordLink`,
  and several `MfaSetupPage.tsx` paths — only the post-password success and passkey paths were
  migrated to `resolveRedirect`.
- **S3 is overstated.** No `GenerateDocumentationFile` is set anywhere (no `Directory.Build.props`,
  not in any csproj), so the XML-doc comments are **not** shipped to consumers' IntelliSense — only
  visible in public source. Two cited locations are wrong: `Authagonal.Protocol/.../AuthorizeEndpoint.cs:80`
  is a plain `//` (not a `///` summary), and `AuthOptions.cs` contains no bullclip/Drawboard text and
  no `#region`. The genuine shipped leak is **N3**.
- **Count/line corrections (substance unaffected):** line numbers drift ~10 low throughout (the
  review was written against a slightly earlier file revision — e.g. H3/L14 cite `:363`, actually
  `:353`); non-en locales number **10**, not 9 (M12); inline-default keys ~24, not ~26 (L13);
  `OidcProviderConfig` has **23** public properties, not ~20 (S2); L10 duplication is across exactly
  **2** stores.
- **The review's own H2 remediation (Phase 1 #4) is partly incoherent** with the stronger fix that
  shipped. "Clear `EmailConfirmed`" would let an unauthenticated attacker de-verify a real user;
  the "Try-vouch carve-out" doesn't map onto deferred provisioning; "fail on zero apps" is
  unnecessary once the inbox click (not the downstream Try) is the proof of ownership. The staged
  `PendingPasswordHash` approach in `86ece22` is the better primitive.

## Verdict 1 — Library integrity: intact, with smells

**Not co-opted.** Every bullclip-motivated feature landed as an opt-in, off-by-default,
generically-expressed mechanism (per-connection config or tenant options). No hardcoded
bullclip/Drawboard identifiers, connection names, domains, or client IDs in shipped code.
`Tcc` = Try-Confirm-Cancel (documented pattern, predates the range), not a product acronym.
Defaults moved toward the *safer* posture where they moved at all (JIT provisioning now
opt-in). `prompt=login` and the federation loop-breaker are spec compliance/robustness,
not product code.

Per-feature: AllowPasswordlessAccountClaim, AllowUninvitedJit, InteractionPath,
AutoLinkExistingByEmail, RevalidateOnRefresh, ProvisioningAttributeParams,
PassthroughParams/UseUpstreamSubjectAsUserId, AllowAnonymousProxyRequests, ws-tickets,
per-login correlation cookie, straight-to-IdP SSO hint, abort-shielding, bulk MFA-status,
invite-vouched verification, ReprovisionAsync — **all judged generic** (opt-in config
usable by any consumer, safe defaults).

### Smells (soft, not co-option)

- **S1 — "Trusted first-party connection" flag cluster.** `UseUpstreamSubjectAsUserId`,
  `AutoLinkExistingByEmail`, `RevalidateOnRefresh`, and softly
  `PassthroughParams`/`InteractionPath` each carry an "only for trusted first-party
  connections" doc warning. That's one trust tier flattened into four independent
  booleans; only a doc comment stops an operator enabling `UseUpstreamSubjectAsUserId`
  on an arbitrary external IdP. Combinatorial interaction with
  `JitProvisioningEnabled`/`AllowedDomains` is where a future misconfiguration lives.
- **S2 — `OidcProviderConfig` grew ~8 → 20 properties**, three of them inverted
  back-compat persistence aliases (justified, but each flag now has multiple spellings).
- **S3 — Consumer name in published XML docs.** bullclip/Drawboard PDF named in
  IntelliSense-visible docs of a shipped package: `OidcProviderConfig.cs` (multiple),
  `Authagonal.Protocol/Endpoints/AuthorizeEndpoint.cs` ("like bullclip's share-link
  handler"), `TableTicketStore.cs` summary, `AuthOptions` region comments.

## Verdict 2 — Quality: good code, worrying process

Substantive changes are above average: small, flag-gated, unusually good "why" comments
including trust-boundary rationale, deliberate back-compat on stored rows (nullable
columns, inverting aliases, legacy-cookie fallback), Dynamo/Azure MFA parity kept, and
the reflective `EntityRoundtripTests` added after the InteractionPath regression is the
right systemic fix. The debits are release-process breakdown, near-zero test coverage on
new features, and a handful of real security-relevant defects.

**Diffstat illusion:** ~95% of the churn in AuthEndpoints/OidcEndpoints/SamlEndpoints/
UserEndpoints is a CRLF→LF rewrite hidden inside feature commits 03ea7a1, 087d23e,
61859b0 (real content: ~68/56/52/20 lines respectively). Blame now dead-ends at commits
describing unrelated features; `.gitattributes` has no `*.cs` rule; `MfaSetupEndpoints.cs`
is still CRLF.

### HIGH

- **H1 — PAR + `prompt=login` infinite login loop.**
  `src/Authagonal.Server/Endpoints/AuthorizeEndpoint.cs:88`. The PAR record is only
  consumed at code issuance (`Authagonal.Protocol/Endpoints/AuthorizeRequestSupport.cs:148`),
  so after forced re-login the return trip reloads the same pushed payload still carrying
  `prompt=login` → forceReauth fires again, forever. `BuildRelativeUrlWithoutPrompt`
  strips only the live query, which for PAR contains no prompt. Comment "the PAR record
  is single-use, so no loop there" is factually wrong.
- **H2 — `AllowPasswordlessAccountClaim` account-takeover surface.**
  `src/Authagonal.Server/Endpoints/AuthEndpoints.cs:374-460`. Claiming sets a password on
  an existing federated account with zero proof the claimant controls the email. SAML-JIT
  users are created `EmailConfirmed = true` (`SamlEndpoints.cs:342`), so the claim returns
  `emailVerified: true`, skips the verification email, and permits immediate password
  sign-in as the victim. Sole defense is a downstream Try handler rejecting — and with no
  provisioning apps configured, `ProvisionAllAsync` returns silently and the claim always
  succeeds. Flag is default-off, but the docs never state the deployment MUST verify
  ownership downstream.
- **H3 — BFF open redirect via backslash.** `src/Authagonal.Bff/BffEndpoints.cs:448`.
  `SanitizeReturnUrl` passes `/\evil.com` (`StartsWith('/')` && not `//`); browsers
  normalize `\`→`/` in Location → protocol-relative redirect. Helper predates the range,
  but the range wired it to two new **unauthenticated** sinks: `/logout?returnUrl=`
  (ade3a7e) and GET `/logout-callback?state=` (`BffEndpoints.cs:363`, redirects with no
  session at all). Note: login-app's client-side `returnUrl.ts` does NOT share this bug —
  its parsed-origin equality check catches both `//` and `/\`.
- **H4 — Releases v0.10.24–v0.10.27 shipped with a non-compiling test project.**
  79557fb added `ReprovisionAsync` to `IProvisioningOrchestrator` but not to
  `TestProvisioningOrchestrator` (`tests/.../Infrastructure/TestServices.cs:92`); fixed
  only after v0.10.27 (4a32135). Verified CS0535 at those tags → `dotnet test` could not
  even build; tests provably not run at release time for four consecutive tags.
- **H5 — tag.sh bypassed; CHANGELOG + version rot.** CHANGELOG newest entry is
  `[0.10.10]`; tags run to v0.10.28 — 18 undocumented releases. tag.sh refuses to tag on
  an empty changelog and sed-bumps `login-app/package.json`, yet package.json sat at
  0.10.14 through v0.10.24 and 0.10.15 for v0.10.25–v0.10.28 → tags minted outside
  tag.sh. This is the exact rot (0.4.0→0.7.8) the script's own comment says it exists to
  prevent.
- **H6 — ~19 of 23 code commits landed with zero test coverage**, including
  security-sensitive surfaces: /logout returnUrl allowlist, AllowUninvitedJit,
  upstream-federated refresh, prompt=login, AutoLinkExistingByEmail + loop-breaker,
  the entire Authagonal.Bff library, and the new 182-line TableTicketStore.
  Covered: InteractionPath (×2 + roundtrip), WebAuthn-index delete,
  AllowPasswordlessAccountClaim (×3).

## Remediation plan

Ordered by risk; each phase is independently shippable. Security first, then process
guardrails (so later fixes go out under discipline), then correctness, then structure.

### Phase 1 — Security fixes (one release, do first)

1. **H3** BFF redirect: in `SanitizeReturnUrl`, reject any `returnUrl` whose first two
   characters contain `\` (mirror ASP.NET `Url.IsLocalUrl` semantics: must start with
   `/`, second char neither `/` nor `\`). Add tests: `/\evil.com`, `//evil.com`,
   `/\t/evil.com`, plus the happy paths, against both `/logout` and `/logout-callback`.
2. **H1** PAR loop: consume/mark the PAR record (or persist a "prompt already honored"
   marker keyed by `request_uri`) when forceReauth redirects, so the return trip does not
   re-see `prompt=login`. Fix the wrong comment. Test: PAR authorize with `prompt=login`
   → login → return → code issued (no loop).
3. **M1** prompt=login enforcement: record `auth_time` at login and, on return to
   authorize with `prompt=login`, require an auth event newer than the original request
   (or sign out the session before showing the form). Test: old-cookie replay of the
   stripped URL is rejected.
4. **H2** passwordless-claim gate: on claim, clear `EmailConfirmed` and require fresh
   email verification **unless** the provisioning Try response explicitly vouches
   (`emailVerified: true`) — reuse the invite-vouch channel from 03ea7a1. Also fail the
   claim (not silently succeed) when zero provisioning apps are configured and the flag
   is on. Document the trust contract on `AllowPasswordlessAccountClaim`.
5. **M2** full rollback on failed upgrade: snapshot the user record before the merge at
